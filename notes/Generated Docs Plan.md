# Generated Docs — Plan

Status: proposal, not started (2026-11-12).

## Goal

Regenerate everything in strvct that is derived from the repo automatically on each release, so it never drifts from its sources:

- the docs HTML, `sitemap.xml`, `llms.txt`, `llms-full.txt` (`node colvmn/static-gen.js`);
- the JSDoc output (`jsdocs/`, from `jsdoc.json`);
- the class hierarchy (`just class-tree` → `docs/class-hierarchy-tree.txt`);
- the build stamp.

Today these are regenerated by hand, so they drift: on 2026-11-12 a regeneration rewrote most of the docs HTML in strvct and 144 files in the Uo repo whose sources had changed since they were last built.

## A Release Is Any Push of Code (decided, Steve, 2026-11-12)

There are no version numbers or tags. Every push of code to `master` is a release.

- **"Of code"** means a push that changes sources. A push that changes only generated output (the files listed above) or the AI Reviews folder is not a release. The workflow excludes those paths (`paths-ignore`), so the regeneration's own commit and the reviews job's commits don't start another release.
- **The build stamp names the commit:** `STRVCT · 2026-11-12 · 3c23b7bb`, the date and short hash of the pushed commit. It changes only when code is pushed, not on rebuilds without new code.

## How

colvmn update jobs with `on: push` (proposed in `colvmn/docs/plans/scheduled-updates/_index.md`): script jobs, deterministic and free, run by a workflow that fires on each push to `master`. Each job watches only its own inputs, so a push runs only the jobs it affects. Their output goes into one follow-up commit ("Regenerate docs for 3c23b7bb").

| Job | Watches |
|---|---|
| Class hierarchy | `source` |
| JSDoc | `source`, `jsdoc.json` |
| Docs HTML, sitemap, llms files, build stamp | `**/_index.md`, `**/_index.json`, `colvmn` |

Editing a doc page doesn't regenerate the JSDoc, and a source change that touches no docs doesn't rebuild every page. The build stamp still names the pushed commit, so it updates whenever the docs are rebuilt.

- **No loop:** the follow-up commit touches only generated files, which the workflow ignores. GitHub also doesn't start new workflow runs for commits pushed with the workflow's own `GITHUB_TOKEN`, which is a second guard.
- **Cost:** one extra commit per push. The alternative is a CI check that fails when the generated output is stale, which leaves regeneration to the author and keeps history to one commit per push, but brings back the drift this plan is meant to end. Auto-regeneration is the choice here.
- **Order:** the docs regenerate first; the AI Reviews job (`notes/AI Reviews Plan.md`) watches the resulting `llms-full.txt` and refreshes on its own schedule, at most once per `minInterval`.

- **Uo pin bumps aren't strvct releases** (confirmed, Steve, 2026-11-12). A Uo push that only bumps strvct's submodule pin pushes no strvct code. strvct's own pushes are its releases.
